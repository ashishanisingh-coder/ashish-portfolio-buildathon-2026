## Production readiness

**Status: ready for final approval; deployment intentionally blocked.**

The isolated static artifact is generated at `dist-v51-pages/` using the new V5.1-only build command. That directory is ignored so the generated artifact does not dirty the working tree.

```bash
npm run build:v51:pages
npm run verify:v51:pages
```

The artifact uses the repository base path `/ashish-portfolio-buildathon-2026/` and contains:

- a root V5.1 homepage;
- `/projects/philips/`;
- `/projects/india/`;
- `/projects/rotavirus/`;

- only the required V5.1 CSS, browser JavaScript, favicon and `assets/actual/` files;
- `.nojekyll` and `v51-pages-manifest.json`.

The existing `scripts/build-static.js` remains the V3 production path. `.github/workflows/pages.yml` still builds the current `site/` V3 website, but it is now manual-only and requires `confirm_v3_release=true`; it no longer runs on pushes to `main`. This prevents an ordinary V3 push workflow from overwriting an approved V5.1 deployment. An intentional V3 rollback remains possible only when someone explicitly runs that workflow and confirms the input.

The approval-gated V5.1 workflow is prepared at `.github/workflows/v51-pages-approval.yml`. It is manual-only, requires an explicit release confirmation input, starts `node v5.1/serve.js`, waits for `http://127.0.0.1:4184/v5.1/` to respond, runs `node v5.1/test.js`, builds and verifies `dist-v51-pages`, uploads that artifact and pauses deployment behind the `v51-pages-approval` GitHub environment. It has not been dispatched.

## Deployment plan — approval required

Do not run the legacy `pages.yml` workflow for V5.1. It is the manual V3 rollback workflow and requires `confirm_v3_release=true`.

After final visual approval:

1. Push the approved V5.1 commits to the repository branch that will be used for the release; keep `main`, `site/` and `v5/` unchanged. This is the only step requiring repository authentication and has not been performed by OmniRush.ai.
2. In **Settings → Pages**, select **GitHub Actions** as the source and configure required reviewers for the `v51-pages-approval` environment.
3. From **Actions**, select **Deploy V5.1 portfolio (approval required)**, choose the approved branch, select `confirm_v51_release=true`, and choose **Run workflow**. The `workflow_dispatch` definition makes this a GitHub-triggerable workflow once the committed workflow file is present on GitHub.
4. Let the build job start the local V5.1 server, wait for readiness, run the route smoke test, run `npm test`, build `dist-v51-pages/` and verify the Pages artifact.
5. Review the build job output and artifact, then approve the `v51-pages-approval` environment when GitHub pauses the deploy job. Do not approve if the reviewed commit or artifact is not the intended one.
6. After deployment approval, verify the public homepage and all four trailing-slash routes, assets, navigation cycle, mobile menu, reduced-motion path, metadata and browser console.
7. Do not run `pages.yml` after V5.1 deployment. Its push trigger is disabled; it can replace V5.1 only through an intentional manual V3 rollback with `confirm_v3_release=true`.
8. If the public site must remain V3, use a separate repository or Pages project for the V5.1 review release rather than replacing the V3 artifact at the existing URL.

## Risks and limitations

- GitHub Pages has no Node server or dynamic route fallback. The four directory-index routes are generated explicitly; arbitrary unknown slugs will not be rendered dynamically.
- The production URL assumes the repository remains named `ashish-portfolio-buildathon-2026`. If the repository name changes, rebuild with `BASE_PATH=/new-repository-name/`.
- GitHub Pages configuration and deployment permissions still require an owner/admin action. No permission or Pages setting was changed.
- Philips and Uno remain truthful source-strip experiences because no separate approved high-resolution panel exports were available.
- The V3 public website is still live and must remain the rollback reference until the final approval decision.
